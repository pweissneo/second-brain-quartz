# Best Practice - Outcome Over Tool

> The tool serves the goal, not the reverse. Focus on what you achieve, not what you use.

## The Principle

Tool overfocus is obsessing over finding the "perfect" tool rather than doing the work. Outcome over tool means focusing on what you accomplish — the tool is just a means to an end.

## The Hierarchy

**What matters:**
- Knowledge that solves problems
- Skills that produce results
- Understanding that enables decisions

**What doesn't matter (much):**
- Which app stores your notes
- Which system organizes your files
- Which method you use to capture

## Why Tools Matter Less

1. **Transferability** — Knowledge transfers across tools; tools don't transfer without knowledge
2. **Convergence** — Most tools do similar things
3. **Lock-in risk** — Over-customizing to a tool makes you dependent

## The Test

Ask: "If I switched tools tomorrow, what would I lose?"

If the answer is "almost nothing," your knowledge is portable. If it's "everything," you're tool-dependent.

## What to Focus On

Instead of tool optimization:
- Capture useful knowledge (format-independent)
- Build skills (tool-agnostic)
- Develop understanding (portable)

The tool is scaffolding — the building matters more.

## The Balance

This doesn't mean ignore tools entirely. Use what works. But don't let tool decisions become procrastination dressed as productivity.
